# 凭证批量提交与字号修复

适用于批量记账后字号与日期顺序不一致，或取消正式凭证后出现断号的情况。

## 在“查凭证”整理编号

例如取消“记1”后，有效凭证剩下“记2、记3”，可将有效凭证整理为“记1、记2”。系统保留原“记1”的取消记录、原字号和分录，不删除历史记录。

1. 使用具有 `Accounts Manager`、`China Finance Manager` 或 `System Manager` 角色且有目标公司、会计凭证读取权限和来源单据读写权限的账号，进入 **中国财务 → 查凭证**。
2. 保存或取消表格内尚未保存的修改，打开右上角菜单中的 **凭证整理编号**。
3. 选择公司、月份、凭证字（默认“记”），填写整理原因。范围为指定公司、整个月份、指定凭证字，包含记账凭证、付款凭证及期末结转凭证，不受当前报表的其他筛选条件限制。
4. 点击 **预览编号**，核对有效凭证数、保留的取消历史数、原字号、新字号及整理后的下一个字号。预览不会修改数据。预览同时统计该公司整月所有凭证字范围的缺失正式凭证数及未提交草稿数；存在已提交但缺少有效正式凭证的单据时，须先补齐或处理异常。草稿不参与本次改号，后续记账或补录可能需要再次整理。
5. 确认无误，勾选 **已确认受影响的打印件和导出文件需要重新生成**，再点击 **确认整理**。如提示数据已变化，重新预览后确认。整月缺失快照及草稿清单也参与预览校验，预览后新增或修改这些单据会要求重新预览。
6. 重新运行“查凭证”，检查有效凭证从 1 连续编号，重新生成受影响的打印件或导出文件。

有效凭证按日期、来源创建时间、来源编号排序，期末结转凭证排在普通凭证之后。查凭证列表按日期展示，同日同凭证字按数字字号排序，待补齐记录和草稿排在当日正式凭证后；列表排序不改号。后续新凭证从整理后的最后一号继续递增；全部凭证已取消的月份，整理后下一张从“记1”开始。不会在日常删除、取消或记账时自动整理。

整理只修改有效凭证及来源显示的字号、编号唯一键和本月编号序列，不改变总账、金额、分录、日期、内部单据编号或现金流量指定关系。来源单据、会计凭证和编号序列记录整理批次及原因，失败整体回滚。有效凭证的新号可能与历史取消凭证的旧号相同，应结合状态和内部单据编号区分。

整理后对当前有效凭证做受控更正，修订凭证继续沿用整理后的字号。整理前已经取消的旧凭证若此后重新修订记账，使用新的号码，不能重新占用已分配给其他有效凭证的旧号。

以下情况不能执行：公司冻结期间、已结账或禁止记账的会计期间、相关凭证已归档或月份已有结账档案包、月末结账正在处理或已准备就绪、存在待处理冲销同步问题，或来源、分录哈希、取消审计不完整。反结账不会自动删除档案包，反结账后仍存在档案包的月份也不能整理。操作时应暂停同月的其他记账、取消、修订及归档工作。

实现入口为 `china_finance/services/voucher_number_organization.py` 和 `china_finance/public/js/voucher_numbering.js`；后续取号复用 `services/voucher.py`，以 `China Voucher Sequence.numbering_revision` 隔离整理前后的编号唯一键。

### 发布与兼容

更新 backend、worker 的代码后，须按现有发布流程同步 `China Voucher Sequence` DocType 并清理缓存，使新增的 `numbering_revision` 字段生效；未整理月份默认版本为 0，保持原取号行为。发布不会自动整理任何历史凭证。

还须执行索引迁移补丁 `v0_6_24.index_voucher_numbering_scope`，其与 `China Accounting Voucher` 的 `on_doctype_update` 共用幂等的索引建立方法，限制锁定查询的扫描范围，避免其他公司的凭证被一并锁定。锁定查询明确使用公司、凭证字、期间和日期的联合索引，发布须完成迁移后再恢复财务操作。整理编号、旧 Bench 排序工具和查凭证更正统一先锁公司，再锁来源凭证。`overrides/source_voucher_lock.py` 通过 `extend_doctype_class` 扩展三类正式来源，在 Frappe 原生保存、提交和取消锁定旧单据前先锁公司，兼容已有 Controller 覆盖；等待后读取最新字号，避免旧表单覆盖整理结果。来源公司在等待期间变化时拒绝保存，要求刷新。此扩展需更新所有 backend、worker 进程并按原流程清理缓存后生效。若数据库返回并发冲突，整次请求应回滚，刷新后重试；不能捕获异常后在原事务中继续记账。业务异常仍使用原保存点回滚，原生事务回滚错误不再被“保存点不存在”掩盖。

编号整理升级需运行站点 `migrate`，为记账凭证、收付款凭证、损益结转凭证同步公司/日期复合索引。执行阶段按该索引限定公司和月份加锁，快照按唯一来源键读取，保留当前读和预览哈希复核。已完成且无错误、无任何总账记录及快照的结转单不需要补齐空凭证；处理中、失败或有总账的结转仍按完整性检查处理。

下面的旧 Bench 排序工具仍保留原行为：只交换本月原号码集合，不填补断号，不支持取消或修订历史。已通过页面整理的月份，后续仍使用页面的“凭证整理编号”，不要混用旧工具。

## 原因与本次修复

字号在记账时生成，按公司、年度、月份和凭证字分别递增。原批量操作直接使用列表勾选顺序；列表通常按最近修改时间倒序，导入较晚的记录反而先提交，所以字号和日期不一致。

更新后，普通批量提交、工作流批量操作及“批量审核并记账”都会先按凭证日期升序处理。同一天按来源单据创建时间、单据编号排序；期末结账批次按期间结束日期排序。原有权限检查、工作流、后台任务及失败处理保持生效。

这是同一批次的排序：分批提交、补录更早日期、并发记账或部分提交失败，仍可能产生日期与字号不完全连续的情况。程序不会在日常记账或更新代码时自动重排已经生成的正式字号。

“查凭证”原来的金额列没有绑定本位币，使用系统默认币种，可能显示 `$`。现在每行分录读取会计凭证的本位币；历史快照未记录币种时使用公司本位币。人民币显示为 CNY 或人民币符号，取决于站点的币种格式设置，不进行汇率换算。

凭证表单、明细、其他报表及打印的同类问题，参见[币种显示统一修复](币种显示统一修复.md)，服务器更新时需要一并执行该文档中的迁移步骤。

## 1. 发布修复

使用现有自定义镜像发布流程更新 `china_finance`，确保 backend 和 worker 使用同一版本并重启相关服务；宿主机只拉代码不保证运行容器已更新。发布过程中按既有流程执行 migrate/清理缓存，让新 hook 生效。

刷新浏览器并重新运行“查凭证”。如果页面显示之前生成的报表，应重新生成结果，不能只查看缓存。该修复没有修改公司或站点的默认币种。

## 2. 预览已生成字号的修复

以下命令在服务器 backend 容器的 `~/frappe-bench` 内执行。以此次新公司 2026 年 5 月为例，整行复制：

```bash
bench --site deeplinkerp.com execute china_finance.services.voucher_number_repair.reorder_monthly_voucher_numbers --kwargs '{"company":"悦为智能技术（东莞）有限公司","accounting_period":"2026-05"}'
```

默认只预览，不修改数据。查看：

- `site`、`company`、`accounting_period`：应是此次服务器新公司和 5 月。
- `voucher_count`：如仅导入了 5 月普通凭证且尚未结转，应为 14；已有其他同月凭证则包含在内。
- `can_apply`：应为 `true`。
- `blockers`：应为空。
- `changes`：逐张列出来源单据、日期、旧字号和新字号。
- `plan_hash`：本次预览的校验值，实际执行时需要使用。

修复范围是指定公司、整个月份、指定凭证字（默认“记”）下的正式凭证，包含 Journal Entry、Payment Entry 和 Period Closing Voucher。按来源日期、来源创建时间、来源编号重排；期末结账凭证排在该月普通凭证之后。复用本月原有号码集合，不填补历史断号、不降低序列计数，也不处理其他月份或其他公司。

工具面向刚导入的、尚未归档的账。存在已取消/冲销、修订链、来源缺失、字号异常、冻结或已封账期间、关联电子档案时会返回阻塞项，不应绕过这些检查。

## 3. 备份后执行

确认预览涉及的全部凭证均应重排。操作期间暂停该公司该月的导入、提交、取消、修改及归档，先做备份：

```bash
bench --site deeplinkerp.com backup --with-files
```

把下面的 `替换为预览返回的plan_hash` 替换为上一步输出的完整校验值，再执行整行：

```bash
bench --site deeplinkerp.com execute china_finance.services.voucher_number_repair.reorder_monthly_voucher_numbers --kwargs '{"company":"悦为智能技术（东莞）有限公司","accounting_period":"2026-05","apply":1,"expected_plan_hash":"替换为预览返回的plan_hash","reason":"修复初次导入凭证批量提交顺序导致的字号倒序"}'
```

如果预览后凭证或流水号发生变化，会提示重新预览。成功返回 `applied: true`。

更新内容是会计凭证的字号、流水号和唯一键，以及来源单据展示的字号；来源和快照均记录旧字号、新字号、批次及原因。所有交换在同一事务中完成，失败时回滚。不会取消并重新提交凭证，也不会改动总账、会计分录、金额、日期、内部单据编号和现金流量指定关联。

## 4. 检查结果

再次执行第 2 步，正常应为 `changed_count: 0`。刷新记账凭证列表，重新运行“查凭证”，核对日期与字号；借贷金额及合计应保持一致。本月后续凭证继续使用原计数器与现有最大号之后的号码。

如果已输出尚未归档的打印件或导出文件，应重新生成，让纸面字号与系统一致。6 月、7 月如已有同样问题，各自预览并处理，不要将月份改成其他公司的会计期间。
