# 凭证准备与月末记账操作

面向财务人员、可直接照步骤执行的完整版，见[银行回单至月末结账与反结账操作 SOP](银行回单至月末结账与反结账SOP.md)。

本次实现的流程：**回单生成草稿 → 查凭证中核对修改 → 试算平衡 → 开始月末结账 → 财务报表 → 确认结账**。

草稿直接使用 Journal Entry 数据，正式记账后才生成总账、正式字号和中国会计凭证快照。日常修改草稿不会产生会计冲销。已经记账的凭证仍使用受控更正，原有历史和归档继续保留。

## 更新服务器

先通过现有发布方式把这次 `china_finance` 代码发布到实际运行的 backend、worker 及静态资源服务。本地改好代码不代表服务器已经更新。

在已更新的 backend 容器 `~/frappe-bench` 下，先备份：

```bash
bench --site deeplinkerp.com backup --with-files
```

如果之前的银行回单第一期已经安装，可以仅同步本次新增字段、报表元数据和菜单。这条命令不自动启用公司、不生成或提交凭证，也不执行科目模板和历史凭证修复：

```bash
bench --site deeplinkerp.com execute china_finance.setup.preparation.sync_preparation_schema
```

如果服务器尚未安装银行回单第一期，应先按[银行回单导入](银行回单导入.md)更新依赖并执行完整迁移。完整 `bench migrate` 也会安装本次字段，无须再重复执行上述同步命令。

```bash
bench --site deeplinkerp.com clear-cache
```

随后按现有 Docker 部署方式重启 backend 和 worker，浏览器 `Ctrl+Shift+R`。新增脚本由 `china_finance/public/js` 提供，应随应用静态资源一起发布，无需改 ERPNext Banking 前端。

本地 `dev.localhost:8000` 和 `aaa:8001` 已同步本次字段与菜单。同步前后的 Journal Entry、GL Entry、Bank Transaction、China Accounting Voucher 数量一致，没有自动开启任何公司的新模式。

## 首次启用，只设置一次

1. 点击“中国财务”，选择实际记账公司。
2. 打开该公司的“中国财务设置”，勾选 **启用凭证准备与月末记账**。
3. 填写 **凭证准备模式生效日期**，建议选择尚未记账的完整月份第一天，例如从 8 月开始处理新业务，就填 `2026-08-01`。不要为了换操作方式把已记账月份退回草稿。
4. 保存。此日期及之后的 Journal Entry 须核对当前版本后才能记账。已记账历史不变；手工、Excel 导入及银行回单草稿共用新流程。

“查凭证”右上菜单也有“凭证准备模式设置”入口。工作台使用原生记账凭证的读取和报表权限，已记账内容还校验会计快照及来源读取权限；仅授权快照的审计用户仍可通过“凭证明细与历史”入口查阅。核对需要财务经理、会计主管或凭证审核角色；实际记账继续校验原生提交权限和已配置的工作流。需要不同人员审核、记账或确认现金流时，由对应人员接续操作。

## 日常操作

### 1. 导入回单

进入“银行与对账 → 银行回单导入”。新业务选择“新业务制证”，历史已记账业务继续用“历史补回单”。

公司、银行账户等信息完整后，上传 PDF 会保存并自动识别。页面显示交易笔数、收入和支出合计、原件及建议科目。普通交易复用银行流水摘要规则，带收款人的“报销/报销款”按当前口径建议到管理费用－办公费。

点击 **确认导入并生成草稿**，系统一次处理本批全部可确定科目的回单，不需要逐笔勾选或先打开核对弹窗。社保按已配置的所属期和比例生成一张五行草稿。

页面显示新增、复用和需处理数量。重复上传或重试不会重新生成已关联的凭证；疑似重复、冲突及缺少科目的记录继续留在原页面，通过“处理异常”单独处理。

点击 **查看本批凭证**，直接进入查凭证并筛选本批次和日期。

### 2. 查凭证与修改

“凭证与结账 → 查凭证”默认显示全部有效凭证，也可筛选未记账、待记账、已记账或已冲销。

点击可编辑的 **科目** 单元格，直接在表内搜索和选择本公司启用的明细科目。候选科目会按原分录币种、应收应付及往来条件过滤；修改后单元格显示待保存状态，并在该凭证的操作列显示 **保存修改** 和 **取消**。同一时间只能编辑一张凭证。

表内可以修改 **科目、摘要**，本位币记账凭证还可以直接点击 **借方、贷方金额** 修改。同一张凭证可以先修改多条分录，最后统一保存；系统不会自动猜测或修改另一侧金额。保存前必须借贷平衡，每条分录不能同时有借方和贷方，也不能两侧都为零。负借方、负贷方沿用原有费用冲减口径，不自动换到另一侧。

关联回单或银行流水时，允许调整费用、计提和个人承担部分的分摊，但银行科目的收付款金额必须保持不变；若原始银行金额有误，应先核对回单及流水，再走完整原单流程。外币或汇率换算凭证、收付款单的计算金额、系统结转金额、合并或拆分显示的金额保持只读。日期、往来单位、成本中心、项目及删除分录继续使用 **打开原单**；增加分录可按下述新增流程操作。冻结或已经结转的期间、已冲销凭证仍不可表内修改。

草稿保存后仍是原来源单据，不产生总账或会计快照；如果原来已经核对，修改内容后核对状态自动失效。已记账凭证第一次点击 **保存修改** 时在表内显示受控更正说明，再点击 **确认更正**；系统在同一事务内取消原凭证、保留冲销历史、生成修订凭证并立即重新记账，原凭证和修订凭证都记录修改前后的科目、摘要或金额，以及操作人和时间。保存或重新记账失败时整体回滚，不保留部分修改。

需要把两行凭证改成三行时，先保存或取消当前表内修改，再点击凭证首行操作列的 **新增一行**（每张凭证只显示一次）。在弹窗中选择 **原分录行**，候选仅包含本次报表中可操作的分录；切换原分录会清空新科目、金额和摘要，重新预览。选择新增分录科目、填写正数的新增行金额，新增摘要留空时沿用原行摘要。例如原贷方 20,000 元拆出 5,000 元，保存后原行贷方为 15,000 元，新增行贷方为 5,000 元，另一侧 20,000 元保持不变；负数冲减仍保留在原借方或贷方，不转换方向。

点击 **预览新增** 核对两个科目和金额；草稿点击 **保存新增**，之后重新核对再记账；已记账凭证点击 **确认更正**，沿用取消、修订、重新记账流程。支持安全快捷核销的凭证会在同一事务内撤销并恢复银行核销；重新记账或核销恢复失败则整体回滚。新增行追加到分录末尾，保留原行的往来单位、成本中心、项目和辅助维度，只允许选择与原行兼容的科目；需要更换这些信息时打开原单。仅支持可唯一对应来源行的本位币 Journal Entry，关联业务单据的分录、外币及计算金额继续在原单处理，新增后最多 100 行。新增及修改同一行的其他内容不能在同一次请求混合提交。

实现入口为 `services/source_voucher_edit.py`、`public/js/voucher_entry_split.js` 和 `china_finance/report/china_voucher_ledger/china_voucher_ledger.js`。开发站点隔离公司的事务回滚测试覆盖草稿、已记账、借贷方向、金额边界、银行核销及异常回滚；前端脚本测试覆盖预览、确认、防重复操作及错误重试；浏览器已验证原生 Frappe 弹窗的单一入口、选行、币种、预览及确认交互，业务接口使用模拟响应，真实站点完整记账与服务器发布待验证。

单笔全额且无歧义的银行核销会自动撤销并恢复到修订凭证；部分核销或多凭证共用流水会阻止保存，并在表内提供银行流水入口。预览打印标记“未记账”，打印的是已保存版本，应先保存科目修改再重新预览。

已核对的草稿发生实质改动后，核对版本自动失效。再次记账必须重新核对，服务端也会阻止从原生表单、批量提交或 API 绕过此检查。

未记账草稿可以在 Journal Entry 列表勾选后通过“操作 → 删除所选未记账草稿”批量删除。回单生成的草稿删除时只解除凭证关联，原回单和银行交易继续保留，该笔回单恢复为“待处理”，可回到原批次重新生成。已经记账或已经取消的凭证属于审计记录，不能用此方式直接删除。

### 3. 核对完成与试算

勾选凭证的任意分录行，点击 **核对所选草稿**。同一凭证勾选多行只处理一次。弹窗集中显示分录和现金流项目，确认后标为“待记账”，此时仍未写总账。

启用了现金流直接指定时，核对弹窗会显示现金流建议；没有可靠项目的凭证须先编辑选择项目。记账后系统把已核对的项目对应到实际总账分录，再执行正常现金流确认。公司启用职责分离时，不能由同一人绕过原有现金流指定/确认限制。

点击 **试算平衡**，查看期初、已记账借贷、草稿借贷及预计余额，金额统一为公司本位币。无法通过验证的草稿会列出原因，并标记试算不完整；更早期间的草稿会单独提示，不能悄悄计入期初。

正式财务报表仍读取实际已记账数据，并提示当前期间另有多少草稿没有计入。基础版本没有把未记账凭证混入三大报表。

## 月末操作

1. 从查凭证点击 **月末结账**，或打开中国财务菜单中的“月末结账”。选择一个 **结账月份**（例如 `2026-08`），系统自动按该月 1 日至月末处理。无需先手工生成损益结转凭证。
2. 点击 **开始月末结账**。系统检查本期回单、全部草稿的核对版本、权限及必要配置；更早期间尚有草稿时需要先处理。
3. 页面逐张显示记账进度，按日期取正式字号，生成正式快照。随后处理回单核销、现金流项目和损益结转。已有业务数据或现金流指定存在问题时，会暂停并显示原因。
4. 状态到“待确认结账”后，点击 **财务报表**。确认结果后点击 **确认结账**，生成报表快照并按公司设置冻结期间，结账档案在后台生成。

当月正式记账前的修改不会冲销；开始月末记账后，已经成功记账的凭证不再作为普通草稿修改。

### 反结账

已结账页面点击 **反结账**，系统会先列出当前及之后所有受影响月份、关联损益结转凭证和反结账后的账务截止日期。填写原因并确认后，系统一次完成：

1. 按月份倒序反结账，恢复到目标月份结账前的账务截止日期。
2. 按月份倒序撤销关联的损益结转凭证和总账，不再要求逐张打开取消。
3. 保留原月末结账单、损益结转凭证、反结账原因和冲销快照，供以后追溯。

反结账完成后，原页面会提供 **查看本期凭证** 和 **重新结账**。先修改或补录凭证，处理完成后点击 **重新结账**，系统带入原公司和期间新建结账单，再按月份正序结账。原结账单显示“已反结账”，无需删除或手工取消。

### 中途失败、关闭页面或重复点击

- 每一步保存进度；关闭页面后，重新打开同一张月末结账单并继续。
- 处理进行中会锁定本期相关写入。需要调整剩余草稿或重新导入时，点击 **暂停**，修正、重新核对后继续。
- 失败不会自动取消已经成功记账的凭证；重试跳过已完成部分，不重复提交、取号或核销。
- 如果损益结转已提交后台任务，暂停不会撤销该任务。遇到结转总账失败，先处理原结转凭证的错误，再继续月末结账。
- 后台总账尚未完成时不会允许结账。结账档案未就绪时页面单独提示，可刷新或点击 **重新生成结账档案**。
- 不要为重试同一月份另建多张月末结账单；继续原结账单即可。一个公司同时只允许一个月末结账任务。

## 范围说明

- 采购/销售发票、付款单等原生业务单据继续保留现有提交记账行为。补回单时关联这些已存在单据，避免再生成一张记账凭证。
- 草稿使用临时编号。正式字号在记账时生成，同批按日期和稳定次序取号；历史字号不自动重排，多批记账或后来补录较早日期的凭证不能保证全月字号严格按日期重排。
- 查凭证默认折叠旧冲销记录，通过状态筛选可继续追溯。已记账或已结账凭证的更正仍需走原来的受控流程。
- 功能只按公司启用；同步代码和字段不会自动变更历史凭证、金额、科目或归档。
