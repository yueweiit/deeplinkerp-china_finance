# 新公司科目模板与启用

适用于服务器上刚建立、使用“中国企业会计准则－一般纳税人制造业（1.0）”生成科目的公司，希望采用本地悦为公司科目体系，并从 **2026-05-01** 按**小企业会计准则**记账。

## 本地核对结果

应用内的 `china_finance/setup/data/yuewei_company_chart.json` 基于本地 `aaa` 站点 `悦为智能技术(东莞)有限公司` 的 335 个启用科目整理，服务器不需要连接本地数据库。

2026-09-20 进一步核对发现：本地 530102 的根类型为 Asset，但父级属于费用，报表类型也仍是 Profit and Loss；旧快照按父级继承类型，导致服务器生成成费用科目。当前模板已将 530102 移至已有的“资产 → 非流动资产 → 开发支出”，其根类型为 Asset、报表类型为 Balance Sheet，科目总数仍为 335。导出工具也会阻止将此类类型与父级不一致的科目再次导出。

这是一份公司的科目模板，不是全体小企业统一适用的法定科目表。它保留了历史细目；未使用的历史科目不用因为出现在模板中就录入业务。

| 配置 | 标准模板 | 公司模板及本次目标 |
| --- | --- | --- |
| 默认应收 | ERPNext 可能选中长期应收款 | 1122 应收账款 |
| 默认应付 | ERPNext 可能选中长期应付款 | 2202 应付账款 |
| 默认成本 | ERPNext 可能选中其他业务成本 | 6401 主营业务成本 |
| 折旧费用 | 660203 管理费用－折旧与摊销 | 660225 管理费用－折旧费 |
| 660203 的含义 | 折旧与摊销 | 物业管理费 |
| 销项税额 | 22210102 | 22210107；公司模板的 22210102 是销项税额抵减 |
| 未分配利润 | 410401 | 410411；公司模板的 410401 是提取法定盈余公积 |
| 101201 的含义 | 银行承兑汇票保证金 | 外埠存款，是否属于现金等价物需复核 |

本地原设置的利润分配科目仍指向 410401、现金流量直接指定启用日期为 2026-08-21，这两项不能照搬。本次只修正代码和提供新公司操作流程，没有改动本地原公司的设置或历史账。

## 1. 更新服务器运行的应用版本

通过现有 `deploy_akivision_apps.sh` / 自定义镜像发布流程更新 `china_finance`，确保 backend、worker 等服务使用同一版本。只在宿主机拉代码，未更新容器中的应用，不一定生效。

进入 backend：

```bash
docker compose -f compose.custom.yaml exec backend bash
```

后续命令均在容器的 `~/frappe-bench` 执行。若发布流程已经执行了 migrate，无需重复；否则执行：

```bash
bench --site deeplinkerp.com migrate
```

拉代码和 migrate 不会自动将现有公司的科目树转换为公司模板。转换必须执行后文指定公司命令。

## 2. 核实新公司名称并备份

```bash
bench --site deeplinkerp.com execute frappe.get_all --kwargs '{"doctype":"Company","fields":["name","abbr","chart_of_accounts"],"limit_page_length":0}'
```

后面的 `服务器新公司全称` 必须替换为输出中的 `name`。中文/英文括号、空格都必须一致。不要误选先前清理测试凭证的 `YUEWEI CN悦为中国`，除非它确实就是此次目标。

```bash
bench --site deeplinkerp.com backup --with-files
```

看到 `Backup for Site deeplinkerp.com has been successfully completed with files` 后继续。转换期间不要在该公司录单、导入数据或让集成系统写入业务。

## 3. 先设置记账口径和日期

服务器网页搜索 `China Finance Settings`（中国财务设置），打开**新公司**对应记录，修改并保存：

| 页面字段 | 设置值 |
| --- | --- |
| 启用中国财务 | 勾选 |
| 会计准则 | 小企业会计准则 |
| 启用日期 | 2026-05-01 |
| 现金流量直接指定启用日期 | 2026-05-01 |
| 法定报表启用日期 | 2026-05-01 |
| 科目映射统一生效日期 | 2026-05-01 |
| 报表金额单位 | 元 |

纳税人类型按照企业实际税务登记填写。“小企业会计准则”不等于“小规模纳税人”；本地为一般纳税人，服务器只有在实际一致时才沿用。当前自动建立的 13% 税费模板也需按实际业务复核。

公司保存时通常已经自动生成财务设置，默认采用“小企业会计准则”；如果没有记录，执行一次初始化：

```bash
bench --site deeplinkerp.com execute china_finance.api.initialize_company --kwargs '{"company":"服务器新公司全称","accounting_standard":"小企业会计准则","activation_date":"2026-05-01"}'
```

然后仍按上表检查全部字段。`initialize_company` 不覆盖已经存在的会计准则和启用日期，不能用重复初始化代替页面修改。

**此时先不要在映射控制台点“复核”或手工调整映射。** 先转换科目，再复核最终结果。

## 4. 预览科目转换

复制整行，替换公司名称后执行：

```bash
bench --site deeplinkerp.com execute china_finance.services.account_template.sync_existing_company_to_template --kwargs '{"company":"服务器新公司全称"}'
```

默认只预览。重点查看：

- `site` 应为 `deeplinkerp.com`，`company` 必须为此次服务器新公司。
- `can_apply` 应为 `true`，`blockers` 应为空。
- `general_ledger_entry_count` 应为 0。
- `missing_count`、`rename_count`、`reparent_count` 分别表示新增、改名、调整父级的数量。
- `configuration_updates` 列出利润分配、税费模板、税务映射和现金范围配套修改。
- `retained_extra_accounts` 是模板之外将保留的科目，因此最终科目总数不一定恰好为 335。

如果已有总账、凭证、订单、收付款、库存、资产等业务数据（包括草稿和已取消记录），或者有人工/已复核映射，工具会阻止转换。存在上下级公司关系时也会阻止转换，避免 ERPNext 将科目改名传播到下级公司。应先核查阻塞项，不要为了通过检查直接删除真实业务。

## 5. 应用转换并检查结果

确认预览目标和范围正确后执行：

```bash
bench --site deeplinkerp.com execute china_finance.services.account_template.sync_existing_company_to_template --kwargs '{"company":"服务器新公司全称","apply":1}'
```

成功返回 `applied: true`。操作包括：

- 按编号匹配科目，补齐缺少科目，调整名称、层级和属性；保留模板外科目。
- 修复公司默认科目和失效的收付款方式科目。
- 将标准模板默认的利润分配科目改为 410411；其他自选利润分配科目需人工核对。
- 将标准销项税引用从 22210102 转到 22210107，涉及销售税费模板和物料税费模板；停用旧普通销项税映射，生成新建议映射。
- 修正未复核的自动现金范围建议：101201 不再自动认作保证金；仍保持待复核。
- 补齐当前会计准则的自动映射，更新未复核自动建议；保留公司设置中的会计准则、日期和权限要求。

转换过程在同一数据库事务中完成，异常时回滚。再次执行预览：

```bash
bench --site deeplinkerp.com execute china_finance.services.account_template.sync_existing_company_to_template --kwargs '{"company":"服务器新公司全称"}'
```

正常新公司应看到 `missing_count: 0`、`rename_count: 0`、`reparent_count: 0`、`configuration_updates: []`。若有 `retained_group_accounts`，表示自有子科目使该科目继续保持分组，需要单独核对。

公司页面的“科目模板”字段可能仍显示标准中国模板名称，这是应用用于识别中国科目配置的内部标记。中国财务设置中的“科目模板”、哈希及完整性检查会按实际识别的公司模板显示，不再拿标准制造业模板比较名称。

## 6. 网页复核后再录期初和正式凭证

在公司页面检查默认科目：现金 1001、银行 100201、应收 1122、应付 2202、收入 6001、成本 6401、折旧 660225。

上述编号表示模板对应的科目范围。适用于全部公司默认科目：若对应科目仍为明细，沿用原模板默认值；若已拆成分组，在公司页面选择其实际科目树下、本公司已启用、根类型及模板要求的科目类型匹配、币种与公司本位币一致的明细科目，也支持跨层级的下级明细。例如 1122 已分组时，可按业务选择 112201 普通客户；不能选择 1122 分组本身、其他分组下仅编码前缀相同的科目或其他公司的科目。初始化、补全主数据及恢复模板默认科目均不会将分组写入公司默认值，也不会自动替财务选择某个子科目；空值或仍指向分组的配置需手动选择后保存。实现见 `china_finance/setup/china_coa_profile.py` 的 `_company_default_matches`、`validate_profile` 和 `apply_company_defaults`。

若月结因“主数据与业务默认科目已就绪”被阻塞，保存正确的默认明细科目后，回到原结账单继续月末结账。此操作不会迁移历史余额、修改已记账分录或调整科目树。以上规则已在源码及隔离单元测试中验证，服务器更新与实际月结待验证。

现金范围同步由同文件的 `ensure_cash_scope` 处理：1001、100201、101201、101299 若为分组，仅为其实际树范围内、本公司已启用的资产类明细生成建议，库存现金及银行存款还须匹配 Cash/Bank 类型；支持多级、无编号及外币明细。保留各编号原有的纳入或排除政策，先应用排除规则，再补充普通 Bank 科目建议；分组本身不创建现金范围。已覆盖期间和人工复核结果不覆盖，提前补齐的期间止于下一段生效日前一天，新增建议均待财务复核。“检查主数据”“补齐空白主数据配置”“同步科目配置”和“恢复模板默认科目”共用此逻辑；已用隔离数据运行实际现金范围 Controller 的校验和期间重叠检查，真实数据库同步仍待验证。

在中国财务设置检查：本年利润 4103、利润分配 **410411 利润分配－未分配利润**。检查销售及物料销项税模板使用 22210107，采购及物料进项税模板使用 22210101。

进入科目映射控制台，选择新公司、**小企业会计准则**对应模板，先核对资产负债表和利润表，再确认现金流分类与现金等价物范围。新增明细的映射需要复核，不要把“已生成建议”等同于“已复核”。日期应覆盖 2026-05-01；有历史建议分段时，要检查各分段连续且分类正确。旧的企业会计准则建议可能仍保留，应以当前所选小企业模板为准。

共享报表模板的生效日期如为 2026-01-01，可以覆盖 5 月，不要为该公司统一改为 5 月 1 日，以免影响其他公司。

在中国财务设置执行“中国科目模板 → 检查主数据”。银行账号、仓库库存科目、收付款方式、客户供应商等仍需按实际业务配置；复制科目不会复制本地公司的银行账号、余额、客户供应商或历史凭证。仓库科目需区分原材料、在产品、库存商品等用途，不要全部套用同一库存商品科目。

2026 会计年度通常为 2026-01-01 至 2026-12-31，正式使用日期是 2026-05-01，两者含义不同。如果公司 5 月前已经经营，先核对截至 4 月 30 日的期初余额及本年累计数据，再安排期初导入；新建 ERP 公司不代表期初余额一定为零。

## 批量导入后的凭证

批量导入后如发现凭证字号未按日期排列，或“查凭证”显示错误币种，参见 [凭证批量提交与字号修复](凭证批量提交与字号修复.md)。代码更新会修正后续批量提交顺序和币种显示；已有字号需按月份单独预览修复。

## 以后新建公司

可以直接选择 `悦为智能技术(东莞)有限公司（公司科目模板）`，创建后按本文第 3、6 步完成启用日期和财务复核。已有业务的公司不要通过改选模板或运行本工具重建科目，应单独制定迁移方案。

## 已同步过旧模板，出现 Needs Attention

若详情包含“科目 530102 根类型应为 Asset”和大量“名称与模板不一致”，原因包含两部分：旧校验器一直使用标准制造业模板；旧公司模板还将 530102 资本化支出放在费用分支。

更新应用并执行 `bench --site deeplinkerp.com migrate` 后，财务设置会按实际公司模板重新校验并显示名称及哈希。已有公司的会计准则不会自动改动；截图中已经选择“小企业会计准则”的公司，继续保留该选择。

对仍无业务、无已复核/人工映射的新公司，备份后重新执行本文第 4、5 步的预览和应用。此次通常只需修复 530102 的父级及类型；完成后应显示 `Ready`。不要仅为了消除提示把检查关闭，也不需要删除重建公司。

如果预览存在阻塞项，应单独核对已有业务和映射；migrate 只刷新配置档案，不会自动移动已存在的科目或修改历史总账。
