# 中国财务入口选择公司

## 操作

1. 首次点击“中国财务”时，若有多家可访问的非集团公司，选择公司后进入工作台；只有一家时自动进入。
2. 再次进入或刷新时沿用当前标签页的公司，不反复弹窗。记住的公司不存在、变为集团公司或已不可访问时重新选择；查询失败会提示重试。
3. 工作台和财务业务页面顶部保留“当前公司”按钮，点击即可切换。弹窗显示最近使用、公司简称、完整名称和中国财务启用情况，也可用 Company 搜索框搜索其他有权限的公司。列表最多显示 20 家，最近使用最多 5 家；未启用状态只作提示，不代替业务初始化。
4. 从中国财务工作台或侧边栏打开查凭证、财务报表和带公司字段的列表，会带入当前公司。带公司筛选的列表新建单据沿用该公司；已保存单据保持原公司。直接打开历史单据时，若顶部工作公司与单据不同，会另行标出单据所属公司；在单据详情点击切换公司后，则进入新公司对应的单据列表，不会更改单据的公司。

取消弹窗保留原选择。校验尚未完成时取消或离开页面，迟到的结果不会修改公司；应用期间显示切换进度并暂时阻止操作。只有新页面数据加载成功后，才更新工作公司、标签页存储和最近使用记录。失败恢复原公司及页面筛选、编辑内容；若页面也无法恢复，则隐藏不可用内容并提供刷新入口。

应用期间通过浏览器后退等方式离开页面，会使本次切换失效；即使随后返回相同地址，旧结果也不提交、不覆盖新页面，受影响的缓存查询页重新进入时须同步公司。单据详情切换到目标公司列表属于本次授权导航，原生路由隐藏选择弹窗不会取消该操作；现金流量指定单列表初始化和后续刷新均使用本次目标公司。

## 切换边界

- 公司按登录用户和浏览器标签页保存。新标签页首次使用可沿用该用户最近一次公司，已打开的标签页互不强制切换；不修改站点或用户默认公司。
- 查凭证、财务报表、科目树及原生列表的单公司筛选与顶部公司同步。科目树首次打开和缓存页重入时，顶部公司、公司下拉框、树根及查询参数须一致；直接带公司参数的科目树链接仍优先使用明确指定的公司。切换时清除旧公司的科目、银行账户、成本中心、项目、账簿等依赖筛选，保留日期、状态等通用条件。同公司跳转保留科目钻取条件。
- 直接链接到报表或列表时，以该页面明确的单公司等值筛选为准；报表首次绑定须等公司确认完成，不能被缓存重入同步覆盖，也不清除链接原有的科目筛选。跨公司、多值或无公司筛选仍属于原生查询，不将它们记作一个公司。
- 查凭证有未保存的分录修改时阻止切换；保存或取消后再切换。标准表单有未保存内容或正在执行结账操作时同样阻止切换，分别提示先保存／放弃修改或等待操作完成。已保存单据切换到另一家公司后，返回同类单据的新公司列表；列表加载失败会回到原单据。既有结账任务始终按原单公司执行。
- 期初余额、现金流量指定工作区复用各自的放弃修改确认和处理中限制；这些编辑页及科目映射控制台正在加载时暂不接受再次切换。取消确认保留编辑内容；新公司加载失败时恢复切换前的客户端内容和选择状态。
- 银行对账切换前提示先保存操作，确认后重新加载界面，等待嵌入应用挂载后才确认切换，再选择该公司的银行账户；加载错误或超时会恢复原公司。嵌入银行对账仅将原生公司存储键映射为当前用户、当前标签页的存储，其他 ERPNext 存储不变；在银行对账内部选择公司也会同步顶部公司。快速连续选择后的校验失败回到顶部最后确认成功的公司，不使用中间尚未确认的选择。
- 公共配置（例如财务报表模板）不强加公司筛选，页面显示“公共配置，不按公司切换”。所有查询、选择和业务操作仍遵循原有权限；选择公司不授予额外权限。

返回已缓存的报表和列表时，按当前工作公司重新加载；若旧报表仍有未保存分录编辑，则保留这些编辑并回到该报表原公司的工作上下文，避免自动丢弃修改。

## 发布与验证

本次新增公司列表只读接口和嵌入银行对账适配脚本，不新增数据库字段，也不修复或重写历史财务数据。需按既有镜像和静态资源发布流程发布 App；生产尚未发布。静态资源应包含 `company_context.js`、`banking_company_context.js` 和 `china_finance.css`。

公司查询入口为 `china_finance.services.company_context.get_company_choices`：使用带权限的 Company 查询，只返回非集团公司；最近使用的名称重新经过权限过滤，启用状态仅对已授权的公司查询。调用方不能用最近使用参数扩大访问范围。

在 App 目录运行：

```bash
node --test china_finance/tests/*.js
python3 -m unittest china_finance.tests.test_company_choices
```

带 Frappe 和 BeautifulSoup 的 bench Python 还可执行 `python -m unittest china_finance.tests.test_banking_i18n`。本地验证不等于生产已上线，真实角色权限、生产银行对账和长任务交互仍须发布后验收。

本次本地结果：193 项前端回归、6 项公司查询接口隔离测试、3 项银行嵌入页测试通过；浏览器使用真实 Frappe Dialog/Link 控件、TreeView/TreeFactory 和树控件，以及隔离数据、延迟响应和故障注入检查，不写入业务单据。前端回归新增 10 项，覆盖现金流详情跳转后的目标公司、初始化重复刷新、首次报表公司确认、加载中离开或返回相同路由、迟到失败、缓存恢复、连续银行选择以及原生路由隐藏弹窗。生产角色、真实银行数据和结账后台任务仍待发布后验证。
